# تدقيق التشغيل الكامل

## الحالة الحالية
قاعدة البيانات تحتوي على المستخدمين، النقاط، الصور، وظائف الاستيراد، سجل التدقيق، أعضاء فريق التوثيق، والنسخ الاحتياطية، مع فهارس أساسية للإحداثيات والحالة والبصمة.

## الفجوات المؤكدة
1. إجراءات التوثيق الحالية محمية بـ `adminProcedure` فقط، لذلك أدوار `reviewer` و`editor` و`import_manager` محفوظة في قاعدة البيانات لكنها لا تُستخدم فعليًا لتفويض العمليات.
2. `atlas_team_members.userId` اختياري، ولا يوجد ربط تلقائي واضح بين البريد المؤسسي والحساب عند أول تسجيل دخول.
3. إنشاء النقطة أصبح يثبت `recordStatus=draft`، وقائمة فريق التوثيق تبدأ بالمسودات.
4. استيراد KML وExcel يمر بالرفع والتخزين والمعاينة والتثبيت والتكرارات والأخطاء، ويحتاج تدقيقًا إضافيًا لحقوق الأدوار وإعادة التشغيل.
5. الواجهة العامة تستخدم السجلات المنشورة فقط، بينما الإدارة والتوثيق منفصلان عن مسار الزوار.
6. إدارة الطبقات المخصصة الحالية تعتمد تخزينًا محليًا في الواجهة، وليست سجلًا خادميًا دائمًا مرتبطًا بقاعدة البيانات.
7. النسخ الاحتياطية تنشئ ملفًا مضغوطًا وتضع سجلًا، وتحتاج تدقيقًا إضافيًا لمسار التنزيل المحمي والاستعادة.

## الأولويات التنفيذية
الأولوية الأولى هي تفويض أدوار فريق التوثيق فعليًا وربط العضو بالحساب، ثم نقل الطبقات المخصصة إلى سجل دائم، ثم إضافة اختبارات تدفق شاملة للدورة: إنشاء، مراجعة، صور، نشر، واستيراد.
